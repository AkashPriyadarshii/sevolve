The evolution loop

Your agent is the subject and the executor. sevolve orchestrates the loop outside it — so every change is observable, revertible, and gated.

sample task → run with current artifact → capture trace → blind grade
↖  promote on held-out  ←  gates pass (size + regression + human) ←  optimizer reflects on the trace ←  score < threshold
↗  version bump  →  PR  →  next run

Why the harness, not the weights

Self-improvement near-term lives in the machinery around the model: skills, prompts, tool descriptions, workflow code. That's files. Files are versionable, testable, and reviewable.

trace-driven

Learn from what actually happened — task, tool calls, failures, output — not from vibes.

blind grader

The judge scores output, never the proposed change. No reward hacking.

gated promotion

Size limits, regression set, tests, human review. --ci skips human, never the gates.

versioned artifacts

Every skill/prompt is a real file with history. Rollback is a git checkout.

Install & run

One package, one API key, no GPU.

# install pip install -e . export ANTHROPIC_API_KEY=... # create a skill, then evolve it sevolve artifact-add skill --name my-skill --file my-skill.md sevolve evolve skill --name my-skill --iterations 5 # → report/report-*.md: before/after scores, cost-vs-delta, REGRESSION summary

Built to be safe to run

The evaluator sits outside the loop

Graders run read-only, in a separate process, blind to proposed changes. The thing that scores can't be gamed.

Promote only on real gain

Held-out score must rise, or nothing ships. No churn of redundant versions.

Capability guardrail

A weak judge model gets logged, not silently trusted. Churn is never silent.

Humans in the loop

Promotion is a PR. Default is human review. `--ci` for CI, never past the mechanical gates.
